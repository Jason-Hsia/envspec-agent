# 闭环优化迭代记录

本文件是「评测闭环真的在起作用」的证据。每一次迭代都由**评测指标驱动**，而不是由"感觉变好了"驱动。

评测集：`data/golden_set.json`，24 题，覆盖 6 个类别（限值直查 / 时效性陷阱 / 适用优先级 / 环评类别 / 拒答 / 多条件约束）。
发布门禁：`src/config.py` 的 `GATES`，其中 `stale_citation_rate` 为**一票否决**。

## 各轮 bad case 归因与修复

### 迭代 1 → 发现 3 类问题

**R1 检索未召回（Q011/Q022）** — 环评类别类问题的 `Recall@5` 为 0。
根因：`wants_eia_class` 的触发正则只覆盖"要不要做环评"，漏掉"需要做环评吗""环评吗"等表述，导致走了通用检索路径而非 `classify_eia_category`。
动作：扩充意图正则；环评类问题不再依赖向量召回，改由工具直答。

**G2 时效性违规（Q004/Q015，违规率 8.3%）** — 答案引用了已废止的 GB 3095-1996。
根因：`_compose` 只把失效标准做成"顶部提示"，但**条文原文仍进入了引用列表**。提示与引用并存，用户复制走的依然是废止条文。
动作：在引用生成处加硬过滤 `and not h.get("is_stale")`，废止标准**只提示、不引用**。
> 这是本项目最重要的一次修复。教训：时效性问题靠"提示语"拦不住，必须在数据结构层面拦截。

**L2 引用精度 0.714** — 限值题把同一污染物的 Ⅲ/Ⅳ/Ⅴ 三档全部倒出，甚至混入被否掉的候选标准。
动作：引用收敛三段式 —— ① 剔除失效版本 ② 有裁决结论时只保留胜出标准的记录 ③ 无裁决时按查询中的等级收敛。

### 迭代 2 → 暴露"地标优先"的误用

**数值准确率回落至 0.929（Q006）**
现象：问"排入地表水Ⅲ类水域的工业废水 COD 限值"，系统答了 DB33 2169（城镇污水处理厂标准）的 30 mg/L，正确答案是 GB 8978 一级标准的 100 mg/L。
根因：`resolve_applicable_standard` 的排序规则只看了"现行有效 + 属地优先 + 标准层级"，**没有校验适用行业**。DB33 只适用于城镇污水处理厂，却被"地方标准优先"这条规则推给了问工业废水的用户。
动作：新增 `industry` 槽位与排序维度 —— 行业不匹配且非通用标准时降级；`通用`/`全国` 视为通配。
> 这是一类"看起来有理、结论错误"的缺陷，指标不暴露就永远发现不了。

### 迭代 3 → 等级约束在工具间丢失

**数值准确率 1.000 但 Q009 仍拿到错误标准**
现象：问"废水氨氮一级排放标准限值"（期望 15 mg/L），裁决环节返回了 DB33 冬季限值 2.5 mg/L。
根因：规划器把 `grade` 传给了 `lookup_limit`，**但没有传给 `resolve_applicable_standard`**。裁决工具在没有等级约束的情况下跨等级重选，把"一级"这个用户已明确给出的条件丢掉了。
动作：`grade` 贯通到裁决工具；裁决只能在其候选集内进行，不得跨等级重选。

**引用精度 0.802（Q012/Q013/Q023）**
根因：正确拒答时本就无引用，但 `citation_precision` 对空引用返回 0.0，系统性拉低均值。
动作：改记 N/A，判据是 `should_refuse`（是否应当作答）而非"有没有引用"，避免把漏引误判成 N/A。
> 指标定义本身的缺陷会被误读成模型缺陷。指标要先自证清白。

### 迭代 4 → 对比类问题被单路裁决

**Q020 数值准确率 0.5**（"地表水Ⅲ类 COD vs 废水一级 COD 有什么区别"）
现象：只回答了废水那一半，地表水限值整个丢失。
根因：`discharge_ctx` 一旦命中就锁定 `water_wastewater`，对比类问题被强行压成单介质查询，再叠加单一裁决，另一半答案被裁掉。
动作：新增"多介质对比"分支做查询分解，每种介质各查一次，且不做单一裁决。

### 迭代 5 → 修完引入的新缺陷

**Q006 再次归零**
根因："多介质对比"的判据写成了 `len(media) > 1`。但"排入地表水Ⅲ类水域的工业废水"同样同时出现地表水与废水 —— 它是**单一问题**（地表水只是用来定级的受纳水体），被误判成对比题后拆成了两路查询。
动作：新增显式对比意图识别（`区别|对比|差异|不同|一样吗|哪个更|vs`），对比分支必须同时满足"多介质 + 有对比词"。
> 闭环的价值就在这里：修复往往会引入新缺陷，只有回归测试能立刻抓住它。

### 迭代 6 → 指标本身在替错误答案背书

**Q006 第三次归零，而且这次是"满分通过"**
现象：Q006 的裁决结论写着"三级，500 mg/L"，标注答案是"一级，100 mg/L"，
但 `numerical_accuracy` 与 `key_point_coverage` **双双给 1.0**，端到端门禁判为通过。
根因有两层：
- **指标定义**：`numerical_accuracy` 问的是"答案正文里出现过 100 吗"。裁决题会把
  候选成套列进正文（一级 100 / 二级 150 / 三级 500），于是错答也能命中。
  指标测的是"提到过"，不是"结论是"。
- **领域逻辑**：GB 8978-1996 §4.2 按**受纳水体**定级。查询里的"Ⅲ类"描述的是受纳水体，
  不是排放等级，需要翻译成"一级"；槽位里没有这层翻译，裁决只能退化为按限值严格程度猜。

动作：① 新增 **结论一致率** 指标，只校验裁决结论句里的唯一结论；
② 新增受纳水体→排放等级映射（Ⅲ类→一级，Ⅳ/Ⅴ类→二级，纳管→三级）。
> 关键点：新指标上线后 Q006 **仍然不及格**，直到定级规则补上才通过。
> 这说明抓到的是真缺陷，而不是把及格线调低了。

**Q014 0.0 —— 新指标上线当天抓到的第二个缺陷**
现象：问"浙江城镇污水处理厂 11月到次年3月的氨氮限值"，裁决结论给的是
常规时段 1.5 mg/L，正确答案是冬季 2.5 mg/L。
根因：同一标准对同一污染物有"常规时段"和"11月1日至次年3月31日"两条限值，
取哪条**与限值严格程度无关**，只与问题有没有限定时期有关。
旧实现用"同分从严"当替代品 —— 等于用限值大小去猜时期。
动作：新增时期槽位（月份/季节/汛期），在 `lookup_limit` 与裁决中作为独立维度，
排在"同分从严"之前。

**门禁有 3/7 项从未生效**
根因：门禁键名写 `recall_at_5`，聚合指标键名是 `recall@5`；
`metrics.get()` 取不到 → `continue` 静默跳过。
7 个门禁里 `recall_at_5` / `tool_selection_accuracy` / `refusal_accuracy` 一直是摆设。
它们当时恰好都达标，所以"24/24 通过"的结论没错，但门禁本身是坏的 ——
报告上"通过"与"没把关"长得一模一样。
动作：指标缺失 = 配置错误 = 按不通过处理；报告显式打印"实际校验 N/M 项"（现为 8/8）。
> 一条门禁如果在取不到值时选择跳过，它就不是门禁，是装饰。

**顺带修掉的两个展示层缺陷**
- `sort` 的"同分从严"写成了 `-value` 升序 = 值最大者优先，与"从严"相反。
- `out/diagnosis.txt` 因 Windows 控制台代码页问题落盘成乱码，而 README 还指着它。
  改为显式 UTF-8 写文件（`eval_report.txt` 早先已用同一手法修过）。

### 迭代 7 → 一条"已知未修"的注释，牵出七层同源缺陷

这一轮的入口不是指标，而是交付前复核时留在架构面板诚实清单里的一条：
`PROTECT_PATTERNS` 在文本 `lower()` 之后匹配大写模式，实际全部失配。
当时判断"当前未启用 jieba 所以未暴露"。实测后确认：**它一直在暴露，只是没人看。**

#### 现象：分词保护层全线失效

`tokenize()` 的第一步是 `text.lower()`，而 `PROTECT_PATTERNS` 里写死了大写
（`GB` / `HJ` / `mg/L` / `PM2.5`）。于是四条保护规则没有一条真正生效。
但"失效"不是"无影响"——它带来的是**静默的语义错乱**：

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | 模式写死大写，文本已 `lower()` | 4/4 条模式全部失配 |
| 2 | 地标格式 `DB33/ 2169-2018`（无 T/Z 段）不被模式 0 覆盖 | **地方标准号根本无法作为整体匹配** |
| 3 | `\b` 在 Python 是 Unicode 语义，`氨氮NH3-N`、`监测PM2.5` 中汉字与字母之间**无词边界** | 污染物代号保护失败 |
| 4 | 罗马数字 `Ⅲ`(U+2162) 经 `lower()` 变成 `ⅲ`(U+2172)，模式类里只有大写形式 | 模式 4 同样失效 |
| 5 | 查询写 ASCII `III类`、数据写 Unicode `Ⅲ类` | 两种写法**永不匹配** |
| 6 | 占位符被降级分词器切成 `值\x01` / `2_` / `0\x01`，垃圾 token 注入词表 | `35 ug/m3` 整个消失 |
| 7 | 哈希向量**没有任何 IDF** | 见下 |

> 第 3 条是排查中最容易走偏的一处：先用正则单独测模式时它是"能匹配"的，
> 因为那时测的是**未 lower 的原始串**。把模式放回真实调用链才暴露 ——
> 单独测函数与测真实链路，结论可以完全相反。

#### 连锁反应：修好分词，检索指标反而掉了

修正分词后，`MRR 0.868 → 0.763`。这一步很关键 —— **如果只盯"修复有没有让指标变好"，
就会把正确的修复回滚掉。** 逐题定位后发现回退集中在 Q002/Q004/Q006/Q019/Q020，
全部是 `PM2.5` / `PM10` / `Ⅲ类` 这类**被新保护模式聚成单个 token 的实体**。

进一步分解 BM25 与向量两条通道：

- **BM25 在两种分词下都把正确条文排在第 1** —— 保护后的实体 token 判别力更强
  （`pm2.5` 只出现在那一条里）。
- **坏的是稠密向量通道** —— 正确条文从向量 rank 1 掉到 rank 7。
- 根因：哈希向量没有 IDF，而 `GB 3095` 表 1 的四行共享同一段章节标题，
  模板用词把真正有判别力的污染物 token 淹掉了。

**于是看清了一个此前不知道的事实：旧指标偏高，来源不是"分词更好"，
而是旧分词把 `PM2.5` 切成 9 个片段，等于意外地给污染物 token 加了 9 倍权重。**
这是一个错误实现碰巧补上了另一个缺失的机制。

动作：给向量通道补上真正的 IDF（这是它本来就缺的东西），
而不是保留"切碎实体"这种意外加权。`MRR → 0.798`。

#### 剩余缺口的两步

**罗马数字归一化 → 0.807。** Q006 查询里写的是 ASCII `III类`，旧分词把它切成
`i`,`i`,`i` —— 在中文文本里这是极罕见字符，一旦有了 IDF 就**霸占查询向量**，
把真正的信号淹掉，`GB 8978-1996#表2-COD` 直接掉出向量 top-20。
把罗马数字（ASCII `III` / Unicode `Ⅲ` / 全角）统一归一到同一 token 后，
两条路径开始指向同一个东西。

**两条召回先验 → 0.833。**

- **污染物命中**：一张限值表里每行只是一个污染物，表标题、单位、等级说明逐字相同，
  纯文本相似度分不出"是哪一行"（实测问 COD 时氨氮行与之并列）。
- **行业不匹配**：`DB33/ 2169-2018` 是**城镇污水处理厂**标准，却排在**工业废水**
  查询的第一行 —— 这正是 `resolve_applicable_standard` 里已经修过的规则，
  召回排序层没有。两条通道各说各话，用户看到的第一条和结论不一致。

> 这两条都不是为指标造的。第二条尤其典型：**同一个领域规则只在一层实现，
> 另一层就会给出相反的答案。**

#### 唯一未修的回退：Q004

`MRR 1.000 → 0.333`，且**只有这一题**。分解后：

| 条文 | 旧分 | 新分 | BM25 名次 | 向量名次 |
|---|---|---|---|---|
| `GB 3095-2012#表1-PM10` | 1.060 | 1.081 | #2 → #2 | #8 → #5 |
| `GB 3095-2012#4.1`（期望） | 1.074 | **1.074** | #6 → #6 | #2 → #2 |

**期望条文自身的两项得分一名未动**，是竞争者（同属 `GB 3095-2012` 的限值行）
在向量通道上升了 3 位。两条都出自同一个标准，最终答案也完全相同：

```
- 规则依据 —— GB 3095-2012 第4.1条：环境空气功能区分为二类……
- 【时效性提示】GB 3095-1996 已被替代，应改用 GB 3095-2012。
```

**决定不修。** 可以加"版本"触发词把 4.1 顶回第一，但那是**为了对齐标注而调参**：
- 该题的两个候选同属一个标准，标注选哪一条有任意性；
- 用 0.10 的加成去翻转 0.007 的差距，说明不了规则稳健，只说明它足够大。

指标下降被如实记录，而不是被悄悄抹平 —— 这是本节存在的意义。

#### 本轮沉淀的判断

1. **"未启用所以未暴露"是一个危险结论。** 实测证明该缺陷一直在生效路径上。
2. **修复可能让指标变差，而指标变差可能恰恰证明修复是对的。**
   这里必须回到逐条证据，不能只看汇总数字。
3. **一个指标偏高的原因，可能是两个错误互相抵消。** 旧分词的"意外 9 倍加权"
   掩盖了向量通道缺 IDF。这种抵消无法通过调参发现，只能通过分解通道发现。

## 复现方式

```bash
python -m src.kb.build_kb        # 建索引
python -m src.eval.run_eval      # 跑评测 -> out/eval_report.json
python -m src.eval.diagnose      # 归因 -> out/diagnosis.json
```

`out/eval_report.json` 含逐题明细与分类别切片，`out/diagnosis.json` 含归因与下轮修复清单。
每次改动后重跑这两条命令，门禁不通过就不允许合并 —— 这是闭环能持续运转的制度保证。
